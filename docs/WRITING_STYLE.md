# Writing standard

GuildGate documentation must be concise, technical, and verifiable.

- Do not translate public API names, error codes, or contract constants.
- Describe security behavior only to the extent supported by source code and tests.
- Replace absolute claims with the actual boundary and the consumer's responsibility.
- Separate the current stable release from historical migration examples.
- Keep the technical meaning of English and Turkish pages aligned.
- Run examples against published export paths and never place secrets in examples.
- Release notes should cover user-visible behavior, compatibility, migrations, and verified results only.
